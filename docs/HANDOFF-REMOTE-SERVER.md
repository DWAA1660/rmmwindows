# Remote support relay — 2026-11-04

## Implemented

- `server/src/support.mjs` adds an attended live support session lifecycle and a `ws` WebSocket relay. `app.mjs` mounts authenticated API routes and exposes `attachSupport(listener)` / `stopSupport()`. `index.mjs` attaches upgrades and closes support before the HTTP listener on shutdown. No Docker socket, command replay, screenshot storage, recording or remote clipboard.
- Additive schemas v6/v7 preserve v5 endpoint groups and persisted run snapshots. `support_sessions` stores hashed scoped device credentials, original operator login hash, lifecycle metadata and job linkage. `support_tickets` contains hashed, one-use browser tickets. Unique active-session index prevents two operators controlling the same device. v7 adds persisted administrator support notification settings and immutable policy snapshots on each session; defaults retain notification with15seconds.
- Creating support requires admin/operator, same-origin CSRF, endpoint inventory reporting agent >=0.1.6, and a caller idempotency key. It queues exactly one internal `remote_support` job with `{sessionId}` and timeout120. Existing `/jobs` validation intentionally rejects that kind, so arbitrary launch identifiers cannot be supplied through generic commands/schedules.
- Agent support claim requires its normal endpoint bearer token, body `{jobId}`, matching running/start-authorized launch job and same endpoint. A synchronous transaction grants a random32-byte support credential only once. Lost credential responses do not authorize another claim. The user companion receives this support credential, never the endpoint agent token.
- Creator-only read, ticket and stop routes; other administrators cannot view/control another administrator's session. Tickets are30seconds, bound to the original creator login and consumed durably at upgrade. WebSocket browser Origin must equal configured `PUBLIC_ORIGIN`; cookies alone do not authorize a stream. The only selected subprotocol is `rmm-support`, never the secret `ticket.*` protocol. Device uses Authorization Bearer; no token query strings.
- WebSockets permit one operator and one device, with no reconnect/resume. Both get state including `session`, `paused`, `controllerConnected`, `reason`; display metadata is forwarded to the operator. `controllerConnected` lets the companion prohibit local capture until an operator browser is actually connected. Server does not forward any frame/input until the companion sends approval; control also requires requested and locally approved control.
- Consent messages optionally report `decision: manual|automatic|unattended`, audited distinctly. Latest user policy was relayed by the root agent: configurable1..300second staff notification/countdown with Decline, automatic approval if not declined, visible active indicator and emergency local hotkey; no staff Stop button. An administrator can turn the approval notice off for unattended use; indicator/hotkey always remain. This overrides the initial project consent/button preference. The companion owns that local interaction; relay only grants sharing after its approval message. `unattended` is rejected when the session snapshot requires notification. `control:false` remains view-only.
- JSON input is sanitized to move/down/up/wheel/keyDown/keyUp/releaseAll. Coordinates normalized0..1, button0/1/2, integral wheel delta ±1200. KeyboardEvent.code allowlist matches companion F1..F12, normal letters/digits/modifiers/navigation/punctuation/numpad. Unknown/bad inputs terminate the session; commands before consent or while paused/view-only are discarded.
- Frames are binary JPEG <=1MiB, no permessage-deflate, max10frames/sec. Slow operator streams drop stale live frames once buffered bytes exceed1MiB; durable job output never uses this relay. Other transport queues >2MiB terminate instead of accumulating input/state.
- Staff decline, stop/emergency exit, either disconnect, protocol violation, expiry, account/session revocation, endpoint revocation or server restart end support and erase its credential/tickets. Original operator account/session and expiry are checked on every message and at least every5seconds. Ping/pong detects dead connections. A failed/interrupted/cancelled launch or120-second nonactive launch deadline frees the endpoint. Awaiting consent adds the snapshotted countdown seconds to that grace, so a300second notice can finish. Active sessions expire30minutes from creation.
- Startup marks all prior nonterminal sessions stopped, never resumed. Ending cancels a launch job only while queued; dispatched/running jobs remain consumed. Jobs may complete after helper bootstrap while the support session continues independently.
- CSP permits the exact configured ws(s) origin and blob images; `/settings.screenViewingEnabled` reflects configured public origin. A browser relay requires PUBLIC_ORIGIN even when ordinary local operator APIs use a Host fallback.
- Native Ctrl+Alt+Del relay extension: device advertises `{type:'capabilities',secureAttention:boolean,secureDesktop:false}`; browser requests `{type:'secureAttention',requestId:UUID}`. Server requires active locally approved control, unpaused desktop, connected controller/device and native capability. Only one pending request, at least5seconds between accepted requests,25second response deadline and no request-ID replay. Requests/results are audited as metadata only. Device result codes `sent|policy_not_enabled|not_available|failed` map to fixed safe UI strings; arbitrary device text is rejected. This requests the service's native SendSAS broker only; no key emulation, policy changes, secure desktop capture or sign-in control.

## API integration contract

- Admin-only `GET/PATCH /api/settings/support` -> raw `{approvalRequired:boolean,approvalSeconds:integer1..300}`. PATCH requires both fields, rejects unknown fields, uses existing same-origin CSRF guard and audits previous/next values. Policy is persisted across database/app reopens; changes only affect newly created sessions.
- `POST /api/support/sessions {endpointId,requestedControl:boolean,idempotencyKey}` -> session directly,201 (idempotent repeat200).
- `GET /api/support/sessions/:id` -> session directly. `POST .../:id/stop {}` -> final session.
- `POST .../:id/ticket {}` -> `{ticket,expiresAt}`.
- `POST /api/agent/support/:id/claim {jobId}` -> `{sessionId,operatorName,expiresAt,requestedControl,approvalRequired,approvalSeconds,credential}`. Session view includes the same policy snapshot. Companion should default optional fields to true/15 only for compatibility with earlier grants.
- WS `/api/support/:id/stream`: browser cookie+Origin, protocols `['rmm-support','ticket.'+ticket]`; device Authorization Bearer credential (optional `rmm-support` protocol).
- Device JSON: consent `{type:'consent',approved,control,userName,decision?}`, display `{type:'display',width,height}`, paused `{type:'paused',paused,reason?}`, stop `{type:'stop',reason?}`. User/device reason strings are deliberately replaced with safe server reasons in audit/state.
- Operator JSON: input `{type:'input',action,x?,y?,button?,deltaY?,key?}`. Device should also locally reject unauthorized input/secure desktop input and release held inputs in all shutdown paths.
- SAS extension: capabilities as above, operator secureAttention UUID, device `{type:'secureAttentionResult',requestId,success,message:code}`; `success:true` only with `sent`. Operator receives fixed human-readable message instead of raw code/text. Successful result means a Windows API request, not proof that a secure desktop was displayed. The companion/service never rewrite Windows SoftwareSASGeneration policy.
- Lifecycle statuses: requested, awaiting_consent, active; terminal declined/stopped/expired/failed. State also reports persistent metadata, final reason and controlApproved. No stream values enter command output, audit details or persistence.

## Limitations / root follow-up

- This is a single-process in-memory relay; horizontal process routing would require an explicit shared session ownership/relay design. Restart deliberately ends all support.
- No actual production staff desktop capture/control was exercised by this server contributor. Browser+Windows integration, packaged update, shared-host nginx WebSocket Upgrade routing and deployment are root responsibilities. Do not report live remote control verified without an explicitly authorized test.
- Agent compatibility gate uses reported inventory, so old endpoints need an updated inventory after upgrade before the button works. Session selection is single endpoint only.
- Primary display only, JPEG stream rather than video codec, no audio/clipboard/file transfer/session recording, no secure desktop/UAC control. Companion is the final authority on active user desktop, visibility, countdown/decline and emergency exit.
- `ws` dependency installed with0reported npm audit vulnerabilities at install time. Official API reference reviewed: https://github.com/websockets/ws/blob/master/doc/ws.md.
