# API contract v1

All paths begin `/api`. JSON, UTC ISO timestamps. Operator routes require an HttpOnly session; state-changing routes require same-origin validation and CSRF header as implemented by server. Agent routes require `Authorization: Bearer <agentToken>` and are isolated from operator sessions.

## Public installer distribution

- `GET /api/agent-download` (no authentication): `{version,runtime,sha256,sizeBytes,downloadUrl,installScriptUrl}`. Whitelisted metadata only; no enrollment credentials. Returns 503 in builds without a package.
- `GET /install.ps1`: bootstrap script with configured HTTPS PUBLIC_ORIGIN, never inferred from request Host headers. No enrollment token embedded. Runs checksum verification before extraction/installation, prompts securely through existing installer. `-DownloadOnly` verifies/extracts without installation or enrollment.
- `GET /downloads/library-rmm-agent-win-x64.zip`: self-contained Windows x64 package as an attachment.
- `GET /downloads/library-rmm-agent-win-x64.zip.sha256`: checksum text. The package is rebuilt with the source inside the Docker build; metadata integrity is checked on server startup. These paths are outside `/api`, except metadata.

Public downloads do not authorize enrollment or management. Authenticated operators still create separate expiring/use-limited tokens; agents still use their own returned bearer credential.

## Agent protocol (owned by server + agent)

- `POST /agent/join` (default, no token, unauthenticated, 30/min/IP): `{deviceId(uuid), joinSecret(32-200 chars), hostname, osName?, osVersion?, domain?, agentVersion?}` -> `{status:"pending"|"denied"}` or, once an operator approved it, `{status:"approved",endpointId,agentToken}`. Server stores only the secret's hash; a different secret for the same deviceId gets 403. Each approved poll ROTATES the agent token (recovers lost responses and restore-on-reboot rollbacks; the previous token stops working). A revoked endpoint is answered `denied`, never re-issued. Max 200 pending requests; pending requests not polled for 14 days are pruned. Agent polls every 30 s pending, 15 min denied.
- `POST /agent/enroll` (optional token path): `{ enrollmentToken, deviceId, hostname }` -> `{endpointId,agentToken}`. Persist token in protected ProgramData; never log.
- `POST /agent/checkin`: `{bootId, inventory}` -> `{endpointId,serverTime,inventoryMinutes}`. `inventoryMinutes` (env `INVENTORY_MINUTES`, default 5, 1-1440) sets how often agents 0.1.3+ send a full inventory; heartbeats stay every 30 s. `inventory` may be omitted for heartbeat. Canonical inventory below.
- `POST /agent/jobs/claim`: `{}` -> `{job:null}` or `{job:{id,kind,payload,dispatchToken,timeoutSeconds}}`. Atomically consumes a queued job, never redelivered. Long-poll: `{waitSeconds:1..25}` holds the request until a job is queued for this endpoint (in-process signal from job creation plus a 2 s re-check) or the wait elapses, then answers the same way. A client that disconnected while waiting never has a job consumed for it. `{}` keeps the old immediate answer. Agents ≥ this release send `waitSeconds:20` (client timeout 30 s) and claim again immediately after an empty answer; after an error, or if an empty answer comes back in under 1 s (old server), they wait `pollSeconds`.
- `PUT /agent/jobs/:id/file/:sequence`: raw `application/octet-stream` body, 1 byte to 4 MiB, for a running `files` `download` job owned by this endpoint. Contiguous sequences from 0; an identical duplicate is accepted (`duplicate:true`), different bytes for a stored sequence or a gap -> 409. 413 when the file would exceed the per-file cap, 507 when the server store total cap is reached.
- `POST /agent/jobs/:id/file/complete`: `{name,sizeBytes,sha256,chunks}`. The server checks size/chunk count and re-hashes the stored bytes (422 on mismatch); idempotent for the same result. A zero-byte file sends no chunks, only this call.
- `POST /agent/jobs/:id/start`: `{dispatchToken}` -> `{mayExecute:true}` only for first valid start. Subsequent starts -> `{mayExecute:false}`. Must receive true before executing.
- `PUT /agent/jobs/:id/output/:sequence`: `{stream:"stdout"|"stderr"|"system",text}`. Contiguous sequence integer starting at 0 across all streams, max 65536 UTF-8 bytes per chunk. Exact duplicate succeeds, mismatched duplicate/gap rejected. Preserve all accepted output. Agent retries upload, never execution.
- `POST /agent/retire` `{}`: the endpoint revokes its own credential (used by the uninstaller); queued jobs are cancelled.
- `POST /agent/jobs/:id/complete`: `{status:"succeeded"|"failed"|"interrupted",exitCode,summary}`. Idempotent matching completion; conflicting completion rejected.

Inventory `{hostname,osName,osVersion,architecture,domain,domainJoined,ipv4:[],loggedOnUser,bootTime,cpuPercent,memoryTotalBytes,memoryUsedBytes,agentVersion,disks:[{name,label,totalBytes,freeBytes}],software:[{name,version,publisher,installDate}]}`. Metrics may be null when unavailable. `bootId` is Windows last boot UTC timestamp.

PowerShell payload `{script}`. The agent's wrapper defines `Invoke-LiveConsole <program> <args>` (runs a console program in a pseudo console through `LibraryRmm.Agent.exe --console-relay` so pipe-buffering tools stream progress live; output is plain UTF-8 text with `\r` progress rewrites, exit code preserved) and `sfc`/`dism` functions that use it; `sfc.exe`/`dism.exe` typed explicitly bypass it. Reboot payload `{delaySeconds:30,reason}` with delay >=30 seconds. Inventory payload `{}`. Storage payload `{path:"C:\\"}` lists direct child file/folder sizes read-only with errors, bounded recursive traversal; emits structured JSON as stdout. No file deletion or arbitrary remote file content route.

Files payload (remote file explorer; requested by the user 2026-11-04). One operation per job, at-most-once like every job; the agent writes one JSON document to stdout and keeps going after per-item errors:
- `{action:"list",path:""}` -> `{action,ok,path:"",drives:[{name,label,type,format,ready,totalBytes,freeBytes}]}`.
- `{action:"list",path}` -> `{action,ok,path,parent,entries:[{name,path,type:"file"|"directory",size,lastWriteTimeUtc,hidden,system,readonly,reparse}],truncated,maxEntries}`. Non-recursive; at most 20,000 entries, and `truncated:true` says so explicitly.
- `{action:"delete",paths:[1..500],recursive}`, `{action:"move"|"copy",sources:[1..500],destinationDirectory,overwrite}`, `{action:"rename",path,newName}`, `{action:"mkdir",path}` -> `{action,ok,succeeded,failed,results:[{path,ok,error,target,note}]}`. Job status `failed` (exit 1) when any item failed; the summary says how many succeeded/failed.
- `{action:"download",path}` -> the agent streams the file through the two agent routes above in 2 MiB chunks with SHA-256, then reports `{action,ok,path,name,size,sha256,chunks}`. Single files only, at most 1 GiB.
- Top-level failure (bad path, folder missing, access denied): `{action,ok:false,error}` and job status `failed`.
- Paths: absolute local `X:\...` only — no UNC, `\\?\`/device paths, `/`, wildcards, alternate data streams or reserved device names; the server rejects these before queueing and the agent re-validates. Names for rename/mkdir cannot contain `\ / : * ? " < > |` or end in a dot/space.
- Agent safety policy (mutations): drive roots, the whole Windows directory, the roots of Program Files / Program Files (x86) / ProgramData / Users (their children may be managed), and the whole agent install and data directories (`%ProgramFiles%\LibraryRmm`, `%ProgramData%\LibraryRmm`, the running agent's own folder and `--data-dir`) are refused, as is anything that contains one of them. Nothing can be copied/moved/created inside the Windows or agent trees. The agent data folder (it holds the agent credential) cannot be downloaded or copied out. Links (symlinks/junctions) are never followed: delete removes the link itself, recursive copy skips links and reports them, links are not downloadable. Read-only files are deleted (attribute cleared). Deletes are permanent (no Recycle Bin). Pasting into the same folder creates `name - Copy`. Moving a folder to another drive copies then deletes the source only if the copy was complete.

## Operator protocol (owned by server + web)

Endpoint groups (organizational, not per-group access control): `GET /groups`, `POST /groups {name,description?}`, `PATCH /groups/:id {name,description?}`, `DELETE /groups/:id {moveToGroupId?}` and `POST /groups/:id/members {endpointIds}`. Admin/operator mutations; viewers read only. Names are unique case-insensitively. Permanent `new-endpoints` / “New endpoints” receives new token-enrolled/approved agents and existing endpoints at migration. Each endpoint has `groupId,groupName`. Bulk moves validate all active endpoints before changing anything; up to10000 per move. Deleting a custom group moves all its endpoints to the selected group (default New endpoints), without deleting endpoints/history. The default cannot be renamed/deleted.

Every `POST /jobs` now creates a persisted run with a snapshot of endpoint IDs; optional `runName` (max150). Existing job limits remain250 per action. `GET /runs` lists the latest100 runs with status counts, and `GET /runs/:id` returns all jobs and original targets. Idempotent job retries do not create another run. Group selection expands to explicit IDs before launching, so later membership changes do not alter an existing run. Script/inventory/reboot multi-computer results use the same live results board; full output remains accessible per job.

Accounts: `auth/me` and login return `{id,username,email,role,disabled}` in `user`. Username login is case-insensitive; email is contact-only with no delivery/reset-email service. Roles: `admin` full access including users/audit/app updates; `operator` endpoint/script/schedule actions; `viewer` read-only fleet/output. Own-account routes are available to all enabled roles.

- `PATCH /account {email,currentPassword}` changes own email.
- `POST /account/password {currentPassword,newPassword}` requires 8–1024 characters and revokes all sessions, including the caller.
- Admin-only `GET /users`, `POST /users {username,email,role,password,currentPassword}`, `PATCH /users/:id {email?,role?,disabled?,password?,currentPassword}`. `currentPassword` is the acting admin's password. Roles/disabling/reset revoke affected sessions immediately. Last enabled admin cannot be disabled/demoted. Accounts are disabled rather than deleted to retain history. No password hashes are returned or audited.

- `GET /health`, `GET /auth/me`, `POST /auth/login {username,password}`, `POST /auth/logout`.
- `GET /overview` -> totals/stats; `GET /endpoints` -> array; `GET /endpoints/:id` -> endpoint incl inventory; `PATCH /endpoints/:id {displayName,tags}`; `POST /endpoints/:id/revoke`.
- `POST /enrollment-tokens {label,maxUses,expiresInHours}` -> token shown once. `GET /enrollment-tokens` lists metadata.
- `GET /join-requests` -> pending first, then decisions from the last 30 days: `[{id,deviceId,hostname,details:{osName,osVersion,domain,agentVersion},remoteIp,status,endpointId,createdAt,lastPollAt,decidedBy,decidedAt}]`. Operators/admins: `POST /join-requests/:id/approve`, `POST /join-requests/:id/deny` (409 once the computer has joined — revoke the endpoint instead), `DELETE /join-requests/:id` (forget a denied/pending request so the device can ask again). All audited (`agent.join.*`).
- `GET /jobs?endpointId=` -> array; `POST /jobs {endpointIds:[],kind,payload,timeoutSeconds?,idempotencyKey?}` -> `{jobs:[]}`; `GET /jobs/:id`; `GET /jobs/:id/output?after=-1&limit=200` -> `{chunks:[{sequence,stream,text}],nextCursor,hasMore}`; `GET /jobs/:id/download` text attachment. `POST /jobs/:id/cancel` only queued jobs can cancel. `kind:"files"` jobs are additionally audited as `files.<action>` with their paths.
- `GET /jobs/:id/file` (operators/admins; viewers 403): the file fetched by a `files` `download` job, streamed as `application/octet-stream` with `Content-Disposition: attachment` (sanitized ASCII name plus RFC 5987 UTF-8 name), `Content-Length` and `X-Content-SHA256`. 409 while still transferring, 410 after expiry. Audited `file.downloaded`. Storage: `<dirname(DATABASE_PATH)>/files/<jobId>.bin` (never the web root); 1 GiB per file, 5 GiB total, deleted 7 days after the transfer started (stalled partial transfers after 24 h) by an hourly cleanup that also removes orphaned files; createApp options `maxFileBytes`, `maxTotalFileBytes`, `fileRetentionMs`, `fileDirectory` override these for tests.
- `GET /scripts` array; `POST /scripts {name,description,body}`; `PUT /scripts/:id {name,description,body}`; `DELETE /scripts/:id`.
- `GET /schedules` array; `POST /schedules {name,scriptId,endpointIds,intervalMinutes,startsAt?,enabled}`; `PATCH /schedules/:id {enabled}`; `DELETE /schedules/:id`. No catch-up replay after downtime, occurrence unique in server ledger.
- `GET /audit?limit=100`; `GET /settings` -> version/update capability etc; `POST /settings/update` requests app image pull/restart, admin-only; `GET /settings/update` -> helper status.

Operator response entities have string UUID `id`. Endpoint includes `displayName,hostname,lastSeen,online,inventory,tags,revoked`. Job includes `id,endpointId,kind,payload,status,createdAt,startedAt,completedAt,summary,exitCode`. Script includes `id,name,description,body,updatedAt`. Schedule includes `id,name,scriptId,endpointIds,intervalMinutes,nextRunAt,enabled`. Errors `{error:string}` with HTTP status. `GET /auth/me` -> `{user:{id,username,email,role:"admin"|"operator"|"viewer",disabled},csrfToken}` or 401.
