# API contract v1

All paths begin `/api`. JSON, UTC ISO timestamps. Operator routes require an HttpOnly session; state-changing routes require same-origin validation and CSRF header as implemented by server. Agent routes require `Authorization: Bearer <agentToken>` and are isolated from operator sessions.

## Public installer distribution

- `GET /api/agent-download` (no authentication): `{version,runtime,sha256,sizeBytes,downloadUrl,installScriptUrl}`. Whitelisted metadata only; no enrollment credentials. Returns 503 in builds without a package.
- `GET /install.ps1`: bootstrap script with configured HTTPS PUBLIC_ORIGIN, never inferred from request Host headers. No enrollment token embedded. Runs checksum verification before extraction/installation, prompts securely through existing installer. `-DownloadOnly` verifies/extracts without installation or enrollment. When any ancestor process is `LibraryRmm.Agent.exe` (an RMM job or terminal), the bootstrap copies itself into a new SYSTEM/Administrators-only `%SystemRoot%TempLibraryRmm-Update-<guid>` folder, registers and starts a trigger-less one-time SYSTEM scheduled task, prints what happened and exits 0. The task waits 20 s, installs, starts the service if it is not running, removes its own task and keeps `update.log` there.
- `GET /downloads/library-rmm-agent-win-x64.zip`: self-contained Windows x64 package as an attachment.
- `GET /downloads/library-rmm-agent-win-x64.zip.sha256`: checksum text. The package is rebuilt with the source inside the Docker build; metadata integrity is checked on server startup. These paths are outside `/api`, except metadata.

Public downloads do not authorize enrollment or management. Authenticated operators still create separate expiring/use-limited tokens; agents still use their own returned bearer credential.

## Agent protocol (owned by server + agent)

- `POST /agent/join` (default, no token, unauthenticated, 30/min/IP): `{deviceId(uuid), joinSecret(32-200 chars), hostname, osName?, osVersion?, domain?, agentVersion?}` -> `{status:"pending"|"denied"}` or, once an operator approved it, `{status:"approved",endpointId,agentToken}`. Server stores only the secret's hash; a different secret for the same deviceId gets 403. Each approved poll ROTATES the agent token (recovers lost responses and restore-on-reboot rollbacks; the previous token stops working). A revoked endpoint is answered `denied`, never re-issued. Max 200 pending requests; pending requests not polled for 14 days are pruned. Agent polls every 30 s pending, 15 min denied.
- `POST /agent/enroll` (optional token path): `{ enrollmentToken, deviceId, hostname }` -> `{endpointId,agentToken}`. Persist token in protected ProgramData; never log.
- `POST /agent/checkin`: `{bootId, inventory}` -> `{endpointId,serverTime,inventoryMinutes}`. `inventoryMinutes` (env `INVENTORY_MINUTES`, default 5, 1-1440) sets how often agents 0.1.3+ send a full inventory; heartbeats stay every 30 s. `inventory` may be omitted for heartbeat. Canonical inventory below.
- `POST /agent/jobs/claim`: `{}` -> `{job:null}` or `{job:{id,kind,payload,dispatchToken,timeoutSeconds}}`. Atomically consumes a queued job, never redelivered. Long-poll: `{waitSeconds:1..25}` holds the request until a job is queued for this endpoint (in-process signal from job creation plus a 2 s re-check) or the wait elapses, then answers the same way. A client that disconnected while waiting never has a job consumed for it. `{}` keeps the old immediate answer. Agents ≥ this release send `waitSeconds:20` (client timeout 30 s) and claim again immediately after an empty answer; after an error, or if an empty answer comes back in under 1 s (old server), they wait `pollSeconds`.
- `PUT /agent/jobs/:id/file/:sequence`: raw `application/octet-stream` body, 1 byte to 4 MiB, for a running `files` `download` job owned by this endpoint. Contiguous sequences from 0; an identical duplicate is accepted (`duplicate:true`), different bytes for a stored sequence or a gap -> 409. 413 when the file would exceed the per-file cap, 507 when the server store total cap is reached.
- `POST /agent/jobs/:id/file/complete`: `{name,sizeBytes,sha256,chunks}`. The server checks size/chunk count and re-hashes the stored bytes (422 on mismatch); idempotent for the same result. A zero-byte file sends no chunks, only this call.
- `POST /agent/jobs/:id/start`: `{dispatchToken}` -> `{mayExecute:true}` only for first valid start. Subsequent starts -> `{mayExecute:false}`. Must receive true before executing.
- `PUT /agent/jobs/:id/output/:sequence`: `{stream:"stdout"|"stderr"|"system",text}`. Contiguous sequence integer starting at 0 across all streams, max 65536 UTF-8 bytes per chunk. Exact duplicate succeeds, mismatched duplicate/gap rejected. Preserve all accepted output. Agent retries upload, never execution.
- `POST /agent/retire` `{}`: the endpoint revokes its own credential (used by the uninstaller); queued jobs are cancelled.
- `POST /agent/jobs/:id/complete`: `{status:"succeeded"|"failed"|"interrupted",exitCode,summary}`. Idempotent matching completion; conflicting completion rejected.

Inventory `{hostname,osName,osVersion,architecture,domain,domainJoined,ipv4:[],loggedOnUser,bootTime,cpuPercent,memoryTotalBytes,memoryUsedBytes,agentVersion,disks:[{name,label,totalBytes,freeBytes}],software:[{name,version,publisher,installDate}]}`. Metrics may be null when unavailable. `bootId` is Windows last boot UTC timestamp.

PowerShell payload `{script}`. The agent's wrapper defines `Invoke-LiveConsole <program> <args>` (runs a console program in a pseudo console through `LibraryRmm.Agent.exe --console-relay` so pipe-buffering tools stream progress live; output is plain UTF-8 text with `\r` progress rewrites, exit code preserved) and `sfc`/`dism` functions that use it; `sfc.exe`/`dism.exe` typed explicitly bypass it. Reboot payload `{delaySeconds:30,reason}` with delay >=30 seconds. Inventory payload `{}`. Storage payload `{path:"C:\\"}` lists direct child file/folder sizes read-only with errors, bounded recursive traversal; emits structured JSON as stdout. No file deletion or arbitrary remote file content route.

Files payload (remote file explorer; requested by the user 2026-11-04). One operation per job, at-most-once like every job; the agent writes one JSON document to stdout and keeps going after per-item errors:
- `{action:"list",path:""}` -> `{action,ok,path:"",drives:[{name,label,type,format,ready,totalBytes,freeBytes}]}`.
- `{action:"list",path}` -> `{action,ok,path,parent,entries:[{name,path,type:"file"|"directory",size,lastWriteTimeUtc,hidden,system,readonly,reparse}],truncated,maxEntries}`. Non-recursive; at most 20,000 entries, and `truncated:true` says so explicitly.
- `{action:"delete",paths:[1..500],recursive}`, `{action:"move"|"copy",sources:[1..500],destinationDirectory,overwrite}`, `{action:"rename",path,newName}`, `{action:"mkdir",path}` -> `{action,ok,succeeded,failed,results:[{path,ok,error,target,note}]}`. Job status `failed` (exit 1) when any item failed; the summary says how many succeeded/failed.
- `{action:"download",path}` -> the agent streams the file through the two agent routes above in 2 MiB chunks with SHA-256, then reports `{action,ok,path,name,size,sha256,chunks,archive:false}`. At most 1 GiB.
- Folder download (agent 0.1.13+; same payload, `path` is a folder): the agent compresses the folder into `<folder>.zip` (top-level entry is the folder itself; empty folders kept; timestamps kept) in `<data-dir>\download-staging`, uploads it through the same routes, and always deletes the temporary zip (stale `*.zip.partial` files older than a day are swept). Result adds `archive:true,files,folders,sourceBytes,skippedCount,skipped:[{path,error}],skippedListTruncated` (`skipped` lists at most 500; `skippedCount` is always exact). Links are never followed, the agent data tree is never included, and files that cannot be opened (in use, access denied) are left out — all listed in `skipped`, job still `succeeded`. A file that fails part-way through reading fails the job and nothing is sent, so a zip never holds a truncated file. Refused: drive roots, folder links, the staging folder, more than 100,000 entries, a zip over 1 GiB, or too little free space on the staging drive (zip size + 512 MiB margin). Agents before 0.1.13 answer folders with `ok:false` ("Folders cannot be downloaded"); the console tells the operator to update the agent. No server change: the stored name is `<folder>.zip` (≤255 characters).
- `{action:"upload",uploadId,destinationDirectory,overwrite}` (agent 0.1.14+): saves a file the operator uploaded (see `/uploads` below). The server **replaces** the payload's `name`, `sizeBytes` and `sha256` with its own record of the finished upload; the browser cannot set them. The agent reads the bytes with `GET /agent/jobs/:id/upload` into a hidden `.rmm-upload-<guid>.partial` in the destination, checks size and SHA-256, then moves it into place (a mismatch or a failed transfer saves nothing). Existing file without `overwrite` -> `ok:false` "... already exists"; existing folder or link with that name is never replaced; read-only files are replaced when `overwrite`. Result `{action,ok,path,name,size,sha256,replaced}`. An expired upload -> `ok:false` asking to upload again.
- `{action:"extract",path,destinationDirectory,overwrite}` (agent 0.1.14+; `path` must end `.zip`): extracts into `destinationDirectory`, creating that one folder if its parent exists. Per entry: names with `..`, empty segments, drive letters, leading `\`/`/`, `:` (streams), reserved device names or invalid characters are refused ("zip slip"); nothing is written through an existing link inside the destination; protected folders stay protected; each file is written to a temporary name and moved into place only when its size matches the declared size and its CRC-32 matches the zip's checksum (so a zip bomb or a lying size cannot fill the disk or leave a truncated file). Limits: 100,000 entries, 16 GiB declared total, free space for that plus 512 MiB. Per-entry failures do not stop the rest. Result `{action,ok,path,destination,createdDestination,files,folders,bytes,succeeded,failed,results:[failures only, at most 500],resultsTruncated}`; status `failed` when any entry failed.
- Write destinations for upload/extract are checked both as typed and as their real final path (every junction, symbolic link and 8.3 short name resolved), so a link in any ancestor cannot lead into the Windows or agent folders; network and drive-letterless targets are refused. Downloads apply the same real-path check for the agent data folder.
- Top-level failure (bad path, folder missing, access denied): `{action,ok:false,error}` and job status `failed`.
- Paths: absolute local `X:\...` only — no UNC, `\\?\`/device paths, `/`, wildcards, alternate data streams or reserved device names; the server rejects these before queueing and the agent re-validates. Names for rename/mkdir cannot contain `\ / : * ? " < > |` or end in a dot/space.
- Agent safety policy (mutations): drive roots, the whole Windows directory, the roots of Program Files / Program Files (x86) / ProgramData / Users (their children may be managed), and the whole agent install and data directories (`%ProgramFiles%\LibraryRmm`, `%ProgramData%\LibraryRmm`, the running agent's own folder and `--data-dir`) are refused, as is anything that contains one of them. Nothing can be copied/moved/created inside the Windows or agent trees. The agent data folder (it holds the agent credential) cannot be downloaded or copied out. Links (symlinks/junctions) are never followed: delete removes the link itself, recursive copy skips links and reports them, links are not downloadable. Read-only files are deleted (attribute cleared). Deletes are permanent (no Recycle Bin). Pasting into the same folder creates `name - Copy`. Moving a folder to another drive copies then deletes the source only if the copy was complete.

## Operator protocol (owned by server + web)

Remote support (agent0.1.6+):

- Admin-only `GET /settings/support` and `PATCH /settings/support {approvalRequired:boolean,approvalSeconds:integer1..300}` persist the global policy (defaulttrue/15). PATCH requires both fields; no unknown fields. Settings are snapshotted into new sessions, not applied to existing sessions. Disabled approval skips the form on a signed-in desktop but never hides the sharing indicator or emergency shortcut.
- `POST /support/sessions {endpointId,requestedControl:boolean,idempotencyKey}` creates one internal at-most-once launch job, returning the session directly. Admin/operators only. Session includes `id,endpointId,endpointName,operatorName,status,expiresAt,requestedControl,controlApproved,approvalRequired,approvalSeconds,jobId,reason,launchSummary`. `reason` is the fixed end-reason code (null while live). `consentUser` is `Windows sign-in screen` for sign-in screen sessions, whose device consent uses `decision:"signin_screen"` (always `approved:true`; allowed even when approval is required because nobody is signed in to notify). `launchSummary` is the launch job's summary (max500 characters) only when `reason` is `launch_failed`; agents 0.1.10+ write a fixed explanation there (e.g. nobody signed in, elevated-only token, helper exited with code N). One active session per endpoint: creating a session ends any open one for that endpoint first (`stopped`, reason `replaced_by_new_session`; a 409 remains only for two creates racing in the same instant). The launch job cannot be created by ordinary `POST /jobs`.
- Creator-only `GET /support/sessions/:id`, `POST /support/sessions/:id/stop {}`, and `POST /support/sessions/:id/ticket {}` (returns one-use `{ticket,expiresAt}`). State changes require cookie/CSRF/Origin. Full lifecycle remains bound to the creator's original login session.
- Agent-authenticated `POST /agent/support/:id/claim {jobId}` requires the matching running launch job, once only; returns `{sessionId,operatorName,expiresAt,requestedControl,approvalRequired,approvalSeconds,credential}`. That limited credential is transferred to the user companion only through the protected pipe.
- WebSocket `/api/support/:id/stream`: browser cookie+exact Origin with protocols `['rmm-support','ticket.'+ticket]`; companion Authorization Bearer scoped credential. Credentials never enter URLs. No reconnect or resume after either transport disconnects.
- Server state `{type:'state',session,paused,controllerConnected,reason}`. Device sends `{type:'consent',approved,control,userName,decision:'manual'|'automatic'|'unattended'}` only once; frames/input are blocked until this local policy completion. Decline/closing refuses; timeout follows the configured admin policy. Persistent visible indicator and Ctrl+Alt+Shift+F12 emergency end remain required.
- Device sends `{type:'display',width,height}`, `{type:'paused',paused,reason?}`, `{type:'stop',reason?}` and binary JPEG<=1MiB. Frames are live only, never persisted; slow receivers drop stale frames. Browser clears pixels on pause/end/disconnect/stale delivery.
- Browser input `{type:'input',action:'move'|'down'|'up'|'wheel'|'keyDown'|'keyUp'|'releaseAll',x?,y?,button?,deltaY?,key?}`: coordinates0..1, buttons0left/1middle/2right, integral wheel±1200, explicit KeyboardEvent.code allowlist. Requires active, unpaused, locally authorized control. Browser starts view-only until Enable control; blur/Escape/stop releases held input. No clipboard, audio, recording or file-transfer channel.
- Device capabilities `{type:'capabilities',secureAttention:boolean,secureDesktop:false}` advertise the real secure-attention broker. Browser `{type:'secureAttention',requestId:UUID}` requires active approved control/capability/unpaused desktop. One pending request,5second rate limit, no replay. Device returns `{type:'secureAttentionResult',requestId,success,message:'sent'|'policy_not_enabled'|'not_available'|'failed'}`; server maps those codes to safe user-facing text and audits metadata. The LocalSystem broker impersonates the target session and calls native SendSAS only if the existing Windows `SoftwareSASGeneration` value permits services(1/3). It never rewrites policy. Success confirms a request, not that Windows switched screens. The non-elevated companion pauses at Winlogon; this does not enable sign-in control.
- Lifecycle: requested→awaiting_consent→active; terminal declined/stopped/expired/failed. Failed launch and bounded launch/notice deadline free the endpoint; active sessions expire30minutes from creation. Ending only cancels still-queued launch work and never requeues dispatched/running jobs. Every logout/account disable/revocation, endpoint revoke, disconnect and server restart ends the live session.

Agents before 0.1.11 require a signed-in active desktop and cannot view or control Windows sign-in/lock/UAC/Ctrl+Alt+Delete screens. Agent 0.1.11+ (SYSTEM screen helper, see ARCHITECTURE.md) can; the protocol additions are:

Agent0.1.12 fixes disconnected-pipe cleanup/takeover and x64 Windows lock-state decoding. It adds no routes or message fields and does not change approval/indicator policy. A failed/dispatched support launch is never replayed; a new operator-created session gets a new authorization.

- Device capabilities may be `{type:'capabilities',secureAttention:boolean,secureDesktop:boolean,deltaFrames?:boolean}`. `secureDesktop:true` changes the Ctrl+Alt+Del success text to say the security screen appears in the viewer. Once `deltaFrames:true` is announced it cannot be withdrawn, and every binary message must be an `RMF1` frame: `"RMF1"`, seq u32, surface width/height u16, flags u8 (bit0 keyframe), rect count u8 (0–64; a keyframe needs ≥1), count × (x,y,w,h u16, jpegLength u32), then exactly those JPEGs (each SOI…EOI, inside the surface), all little-endian, ≤1 MiB. Anything else ends the session `invalid_frame`. 30 frames/s and 120 device messages/s maximum (browser 240/s).
- Browser `{type:'frameAck',seq}` (integer 0…2³²−1) is forwarded to the device for flow control; `{type:'refresh'}` (≤4/s) is forwarded as `{type:'keyframe'}`. Both are ignored for agents without delta frames. When the relay must drop a frame for a slow browser, or after the device resumes from a pause or the browser asks for a refresh, it relays no patches until a keyframe and sends the device `{type:'keyframe'}`.
- Device `{type:'paused',paused,reason}` reasons `waiting_for_user`, `desktop_unavailable`, `selecting_display`, `display_configuration_changed` map to fixed operator text; others show the generic text.
- Device `{type:'userConsent',approved,control,userName,decision:'manual'|'automatic'|'unattended'}` is accepted only while active (someone signed in during a sign-in/lock-screen session and answered the notice). It updates `consentUser` and `controlApproved` (control withdrawn releases input), is audited as `support.consent` with `phase:'user_signed_in'`; `approved:false` ends the session `declined`/`staff_declined`. `unattended` is refused when the snapshot requires approval.
- Device `{type:'stop',reason}` keeps these reasons as the session's `reason`: `local_emergency_hotkey`, `staff_declined` (status `declined`), `staff_closed`, `notice_closed`, `console_session_changed`, `capture_or_relay_failed`, `management_service_disconnected`, `selected_display_unavailable`, `session_expired`, `emergency_hotkey_unavailable`; anything else is `staff_stopped`.
- Consent `userName` is `Windows sign-in screen` (nobody signed in) or `Windows lock screen` (session locked at start) for `decision:'signin_screen'`. See remote component handoffs for native secure-attention capability and verification limits.

Endpoint groups (organizational, not per-group access control): `GET /groups`, `POST /groups {name,description?}`, `PATCH /groups/:id {name,description?}`, `DELETE /groups/:id {moveToGroupId?}` and `POST /groups/:id/members {endpointIds}`. Admin/operator mutations; viewers read only. Names are unique case-insensitively. Permanent `new-endpoints` / “New endpoints” receives new token-enrolled/approved agents and existing endpoints at migration. Each endpoint has `groupId,groupName`. Bulk moves validate all active endpoints before changing anything; up to10000 per move. Deleting a custom group moves all its endpoints to the selected group (default New endpoints), without deleting endpoints/history. The default cannot be renamed/deleted.

Every `POST /jobs` now creates a persisted run with a snapshot of endpoint IDs; optional `runName` (max150). Existing job limits remain250 per action. `GET /runs` lists the latest100 runs with status counts, and `GET /runs/:id` returns all jobs and original targets. Idempotent job retries do not create another run. Group selection expands to explicit IDs before launching, so later membership changes do not alter an existing run. Script/inventory/reboot multi-computer results use the same live results board; full output remains accessible per job.

Accounts: `auth/me` and login return `{id,username,email,role,disabled}` in `user`. Username login is case-insensitive; email is contact-only with no delivery/reset-email service. Roles: `admin` full access including users/audit/app updates; `operator` endpoint/script/schedule actions; `viewer` read-only fleet/output. Own-account routes are available to all enabled roles.

- `PATCH /account {email,currentPassword}` changes own email.
- `POST /account/password {currentPassword,newPassword}` requires 8–1024 characters and revokes all sessions, including the caller.
- Admin-only `GET /users`, `POST /users {username,email,role,password,currentPassword}`, `PATCH /users/:id {email?,role?,disabled?,password?,currentPassword}`. `currentPassword` is the acting admin's password. Roles/disabling/reset revoke affected sessions immediately. Last enabled admin cannot be disabled/demoted. Accounts are disabled rather than deleted to retain history. No password hashes are returned or audited.

- `GET /health`, `GET /auth/me`, `POST /auth/login {username,password}`, `POST /auth/logout`.
- `GET /overview` -> totals/stats; `GET /endpoints` -> array; `GET /endpoints/:id` -> endpoint incl inventory; `PATCH /endpoints/:id {displayName,tags}`; `POST /endpoints/:id/revoke`.
- `POST /enrollment-tokens {label,maxUses,expiresInHours}` -> token shown once. `GET /enrollment-tokens` lists metadata.
- `GET /join-requests` -> pending first, then decisions from the last 30 days: `[{id,deviceId,hostname,details:{osName,osVersion,domain,agentVersion},remoteIp,status,endpointId,createdAt,lastPollAt,decidedBy,decidedAt}]`. Operators/admins: `POST /join-requests/:id/approve`, `POST /join-requests/:id/deny` (409 once the computer has joined — revoke the endpoint instead), `DELETE /join-requests/:id` (forget a denied/pending request so the device can ask again). All audited (`agent.join.*`).
- `GET /jobs?endpointId=` -> array; `POST /jobs {endpointIds:[],kind,payload,timeoutSeconds?,idempotencyKey?}` -> `{jobs:[]}`; `GET /jobs/:id`; `GET /jobs/:id/output?after=-1&limit=200` -> `{chunks:[{sequence,stream,text}],nextCursor,hasMore}`; `GET /jobs/:id/download` text attachment. `POST /jobs/:id/cancel` only queued jobs can cancel. `kind:"files"` jobs are additionally audited as `files.<action>` with their paths.
- `GET /jobs/:id/file` (operators/admins; viewers 403): the file fetched by a `files` `download` job, streamed as `application/octet-stream` with `Content-Disposition: attachment` (sanitized ASCII name plus RFC 5987 UTF-8 name), `Content-Length` and `X-Content-SHA256`. 409 while still transferring, 410 after expiry. Audited `file.downloaded`. Storage: `<dirname(DATABASE_PATH)>/files/<jobId>.bin` (never the web root); 1 GiB per file, 5 GiB total, deleted 7 days after the transfer started (stalled partial transfers after 24 h) by an hourly cleanup that also removes orphaned files; createApp options `maxFileBytes`, `maxTotalFileBytes`, `fileRetentionMs`, `fileDirectory` override these for tests.
- Uploads (operators/admins; viewers 403; cookie + CSRF + Origin like every mutation), schema 11. Bytes are stored as `<files>/uploads/<uuid>.partial|.upload` — never under the uploaded name, never in the web root — and count against the same 5 GiB total cap as downloads (the declared size is reserved when the upload starts).
  - `POST /uploads {name,sizeBytes}` -> 201 `{id,name,sizeBytes,receivedBytes,status:"receiving",sha256:null,chunkBytes}`. `name` follows the rename rules (no `\ / : * ? " < > |`, reserved names or trailing dot/space, ≤255); `sizeBytes` 0…1 GiB. 507 when the store would exceed its cap, 429 with 20 unfinished uploads per account.
  - `PUT /uploads/:id/chunks/:sequence` raw `application/octet-stream`, 1 byte–4 MiB, contiguous from 0; identical duplicate accepted, different bytes or a gap 409, more than declared 413.
  - `POST /uploads/:id/complete {}` -> the server hashes the stored bytes and returns `status:"complete"` with `sha256`; idempotent. 409 until every byte arrived.
  - `DELETE /uploads/:id` discards it (409 while a job delivering it is still queued/running).
  - Only the account that created an upload can add to, finish, delete or send it (others get 404). Unfinished uploads expire after 24 h idle; finished ones a day after creation if never sent, one hour after the last job delivering them finished, and always after 7 days. Audited `file.upload.started|received|deleted|expired` plus `files.upload` per job.
- Agent `GET /agent/jobs/:id/upload?offset=&length=` (bearer): `length` 1–4 MiB from `offset` of the upload named by this endpoint's own `files`/`upload` job, only while that job is `running` (after start authorization); another endpoint's job 404, wrong state 409, expired 410. `X-Content-SHA256` carries the expected hash.
- `POST /endpoints/:id/update-agent {idempotencyKey}` (operators/admins; viewers 403) -> `{job,duplicate}`, 201 new / 200 same key. Queues one `powershell` job with a fixed server-written script that runs `<PUBLIC_ORIGIN>/install.ps1`; the browser never supplies the script. 409 while an identical update job for that endpoint is queued/dispatched/running, or for a revoked endpoint; 404 unknown endpoint. Audited `agent.update.requested`. At-most-once like every job; a finished/interrupted update is never requeued. The bootstrap notices it was started by the agent and continues in a one-time SYSTEM scheduled task (see Public installer distribution), so the restart cannot kill the installer.
- `POST /endpoints/update-agent {endpointIds:string[1..250], idempotencyKey}` (operators/admins; viewers 403) -> `{runId,duplicate,results:[{endpointId,endpointName,status:"queued"|"skipped",reason?,job?}]}`, 201 new / 200 same key (409 if that key was used for a different selection). Bulk form of the route above: the same fixed server-written job, one per computer, all in one run named `Agent update · N computers` (`runId` null when nothing was queued). Computers with an update already queued/dispatched/running, revoked or unknown are skipped with a reason; duplicate IDs collapse. Audited `agent.update.requested` per job with `bulk:true`. Nothing is retried or requeued.
- Groups include `autoUpdate:boolean` (schema 10, default true). `PUT /groups/:id/auto-update {autoUpdate:boolean}` (operators/admins, any group including New endpoints) -> group; audited `group.auto_update.changed`. It only controls agents' own automatic checks; `update-agent` still works. Agents older than 0.1.9 ignore it because they only read the anonymous manifest.
- `GET /scripts` array; `POST /scripts {name,description,body}`; `PUT /scripts/:id {name,description,body}`; `DELETE /scripts/:id`.
- `GET /schedules` array; `POST /schedules {name,scriptId,endpointIds,intervalMinutes,startsAt?,enabled}`; `PATCH /schedules/:id {enabled}`; `DELETE /schedules/:id`. No catch-up replay after downtime, occurrence unique in server ledger.
- `GET /audit?limit=100`; `GET /settings` -> version/update capability etc; `POST /settings/update` requests app image pull/restart, admin-only; `GET /settings/update` -> helper status.

Operator response entities have string UUID `id`. Endpoint includes `displayName,hostname,lastSeen,online,inventory,tags,revoked`. Job includes `id,endpointId,kind,payload,status,createdAt,startedAt,completedAt,summary,exitCode`. Script includes `id,name,description,body,updatedAt`. Schedule includes `id,name,scriptId,endpointIds,intervalMinutes,nextRunAt,enabled`. Errors `{error:string}` with HTTP status. `GET /auth/me` -> `{user:{id,username,email,role:"admin"|"operator"|"viewer",disabled},csrfToken}` or 401.

## Agent update health (agent0.1.8+, schema9)

- Bearer-only `POST /agent/update-status {updateStatus}` reports startup/download/install evidence before normal inventory or job claims. The body permits only that required property. Returns `{endpointId,serverTime}`; atomically updates endpoint lastSeen and updater evidence without changing bootId or inventory. Operator cookies/CSRF do not authorize this route. Endpoint scope always comes from the agent credential, never report content.
- `GET /agent/update-manifest` (agent 0.1.9+, bearer) -> the public manifest fields plus `autoUpdate:boolean`, the endpoint group's setting. 503 without a package. Agents call this first and fall back to the anonymous `/api/agent-download` only on 404 (older server); any other refusal stops the check. With `autoUpdate:false` the agent reports phase `disabled`, stage `policy`, code `group_disabled`, and downloads nothing.
- Existing bearer-only `POST /agent/checkin` accepts optional top-level `updateStatus`. Omission preserves prior evidence and its original receivedAt; explicit null is invalid. Telemetry and inventory validate first, then heartbeat/inventory/report commit in one transaction. Invalid report or inventory returns400 without replacing either prior snapshot.
- Authenticated read-only `GET /agent-updates` supports existing admin/operator/viewer roles and returns an **array** of nonrevoked endpoint rows `{endpointId,endpointName,hostname,online,lastSeen,agentVersion,updateStatus}`. `updateStatus` is null for an endpoint that has not reported updater telemetry; this means unknown, including older agents, rather than failure. `/endpoints` and `/endpoints/:id` also include this nullable property separate from inventory. Current website package metadata remains available through `/agent-download`.

The report is `{schemaVersion:1,installedVersion,availableVersion?,phase,stage,checkedAt,lastAttemptAt?,nextRetryAt?,attempts,errorCode?,summary?,packageSha256?}`. Optional fields normalize to null; server adds `receivedAt` from its own UTC clock. Use receivedAt for freshness; checkedAt/attempt/retry timestamps come from the endpoint and require ISO timestamps with timezone (max64 characters, normalized to UTC milliseconds).

Phases: `disabled`, `checking`, `current`, `deferred`, `downloading`, `verifying`, `installing`, `failed`, `retry_wait`, `unsupported`. Stages: `manifest`, `download`, `verify`, `extract`, `launch`, `install`, `complete`, `policy`. Attempts are integers0–3. Versions are bounded ASCII `N.N.N` (1–6 digits per component) with optional bounded prerelease/build suffix, max104 characters. Package SHA256 is null or exactly64 hexadecimal characters, normalized lowercase.

Error codes are the closed safe enum `disabled`, `unsupported_install`, `deferred_busy`, `dns_error`, `tls_error`, `network_error`, `request_timeout`, `http_error`, `manifest_invalid`, `checksum_mismatch`, `extract_failed`, `launch_failed`, `install_failed`, `pipeline_stopped`, `helper_stalled`, `attempt_limit`, `retry_backoff`, `state_invalid`, `cancelled`, `unknown_failure`. Max80 characters; arbitrary error text is rejected. The server derives summary from the exact fixed phase/error catalog shared with `agent/UpdateDiagnostics.cs`; supplied summary (max400) must match it. Unknown fields, raw logs, credentials, paths/URLs, arbitrary summaries, nested objects, endpointId and caller-supplied receivedAt are not accepted or echoed.

Schema9 stores latest evidence and at most100 semantic transitions per endpoint. Timestamp-only updates refresh latest evidence without growing history. Failure transitions audit only safe phase/stage/code/attempt/version metadata; repeated identical reports do not duplicate audit/history. Pruning applies only to updater transition rows and never to jobs, command output or consumed authorization. Reporting creates no scripts, remote commands or automatic execution retries. See [server updater handoff](HANDOFF-UPDATE-SERVER.md) for full validation and test evidence.
